# Running the benchmarks on another machine

One script per platform builds Release, runs the tests and the differential-fuzz gate, runs the
benchmarks and writes everything to `bench/results/platforms/<id>/` (one JSON file per run, a
`machine.txt` with the hardware and thermal state, and a generated `SUMMARY.md`).

| Platform | Command |
|---|---|
| macOS, Apple Silicon | `scripts/bench_macos.sh` |
| Windows (MSVC + conda env, see [BENCHMARKING.md](BENCHMARKING.md)) | `scripts\bench_windows.ps1` |

Both take a quick mode (`--quick` / `-Quick`, about five minutes) that only proves the setup works.
Do not publish quick-mode numbers. Both can also replay the real Nasdaq data (`--itch FILE` /
`-Itch FILE`); that file is several GB, is not in the repository and must never be committed.

## macOS, step by step

1. Install the Xcode command line tools (`xcode-select --install`) and Homebrew (<https://brew.sh>).
2. Clone the repository:
   ```
   gh repo clone alags21/lob-engine && cd lob-engine
   ```
3. Plug in the charger, turn Low Power Mode off, quit heavy apps, leave the lid open.
4. Smoke test, then the full run:
   ```
   scripts/bench_macos.sh --quick
   scripts/bench_macos.sh --itch ~/path/to/07302019.NASDAQ_ITCH50.gz     # omit --itch if the file is not on this Mac
   ```
   The script checks the machine state, installs missing tools with Homebrew (`cmake`, `ninja`,
   `googletest`), keeps the Mac awake with `caffeinate`, pauses between phases so a fanless machine can
   cool, and prints the commands to commit or send back the results at the end.

## What differs on Apple Silicon (and is recorded in the result files)

- **Timer resolution.** The only user-space timer is the 24 MHz architected counter
  (`CNTVCT_EL0`), so one tick is about 41.7 ns. Per-operation latency percentiles are multiples of
  that step; throughput (wall clock over the whole loop) is not affected. The clock name in every
  JSON file states the resolution, and `SUMMARY.md` repeats the warning.
- **No thread pinning.** macOS has no affinity API. The benchmark threads ask for the
  user-interactive QoS class (which prefers performance cores) but can migrate; result files record
  `pinned_cpu: -1`.
- **Cache line.** Apple M-series cores use 128-byte cache lines, so `lob::kCacheLine` is 128 there
  (64 elsewhere). The padded-versus-unpadded SPSC comparison is only meaningful with the right size.
- **Memory model.** arm64 is weakly ordered; the SPSC ring uses acquire/release and is therefore
  correct, but x86 hides ordering mistakes that arm64 does not, so a clean run here is extra evidence.
- **Thermals.** A fanless MacBook Air throttles under sustained load. The script records
  `pmset -g therm` before and after; large run-to-run variance (the CV columns) is the symptom.

## Reading the results

`SUMMARY.md` is generated by `scripts/summarize_platform.py` from the JSON files; nothing in it is
typed by hand. Compare ratios between designs on the same machine (SPSC versus mutex queue, final
engine versus baseline), not absolute numbers across machines: the machines differ in core type,
clock, timer resolution and isolation.
