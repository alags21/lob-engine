## Mapping ITCH to the engine (as implemented in `itch/itch_validate.cpp`)

| ITCH | Engine operation |
|---|---|
| A / F | submit limit GTC (id = order reference, price in 1/10000 dollar = integer ticks). If it would cross or lock our uncrossed book it is counted (`adds_that_would_cross_our_book`) and not inserted |
| D | cancel |
| X | partial cancel = `modify` down at the same price (keeps priority, same as the engine's modify rule); to zero = cancel |
| U | cancel + new order with the new reference (new queue position). Experiment switch `--replace-keeps-priority 1` keeps priority when the price is unchanged and the size does not increase |
| E / C | submit a marketable IOC on the opposite side at the executed order's price for the executed size; the ENGINE chooses the maker. Expected: exactly one trade against the executed reference at that price and size. C executions never print at the order's price (all C in the probe differ), which is why the order's own price is used |
| P, Q | counted only (non-displayed / cross prints do not touch the displayed book) |
| S, H, Q(cross) | define the phase: before `S Q` = pre-market, between `S Q` and `S M` = market hours, after = post-close. A symbol is in the continuous bucket when the phase is market hours, its trading state is `T`, it has had its opening cross and not its closing cross |

Why a pass of the priority check is meaningful: the IOC does not name the maker. If the engine's price-time
rules, the modify rule, or the replace handling differed from the exchange's for the book state built only
from add/cancel/replace messages, the engine would hit a different order and the check fails (the unit tests
contain such cases). A trivially "echoing" implementation could not fail; ours can, and does (see below).
After a disagreement the symbol's book is rebuilt from the exchange-implied state (arrival order) so one
disagreement does not cascade.

Three checks (all in `lob_itch validate`): (a) order-level consistency (E/C/X/D/U reference a live order,
sizes cannot be exceeded, our book's size equals the exchange-implied size); (b) the priority check above;
(c) selected symbols also feed the Stage 2 reference book and BBO, every level aggregate and every queue
order are compared every N messages.

## Results so far (exploratory probes, older binary versions; full-day results TODO)

Probe files: `probe_0.json` (first 30M messages, all symbols, baseline semantics), `probe_1.json` (same
with `--replace-keeps-priority 1`), `probe_4.json` (first 60M messages, SPY/AAPL/MSFT only, with taxonomy),
`probe_5.json` (same with `--x-loses-priority 1`).

- Order-level violations: **zero** in every probe (unknown reference, duplicate reference, over-execute,
  over-cancel, book size differing from the exchange, book rejecting an operation).
- Priority check, continuous hours, first 30M messages, all symbols: 467,700 executions checked, 9,333
  (about 2.0%) executed a different same-price order than strict FIFO would pick. No "better-priced order
  ahead" cases and no "no fill" cases: every disagreement was among orders at the same price.
- SPY/AAPL/MSFT, first 60M messages (`probe_4`): 31,266 continuous executions checked, 658 disagreements
  (about 2.1%). Reference-model cross-check was exercised in earlier probes with AAPL; the full-day runs
  with five reference symbols were not finished.
- The real-stream replay benchmark has NOT been run yet.

## Hypotheses for the same-price disagreements (rules: do not change the engine to hide them)

| # | Hypothesis | Status |
|---|---|---|
| 1 | Self-match prevention (skip same-participant same-price order) | **Untestable from ITCH**: executions do not name the aggressor; only F orders carry an MPID, and no mismatch in the probe involved an F order (0 of 658) |
| 2 | Pegged / repriced orders re-ranked without a visible U | **Partly untestable**: ITCH has no price-change message other than U (which is handled). All C executions print at a price different from the order's (514 of 514 in the probe), but E has no price field, so a silent reprice cannot be observed |
| 3 | Non-displayed / reserve interest | **Pending**: the tool now writes `--symbols-csv` (per-symbol activity incl. P-trade share volume) to correlate mismatch rate with non-displayed activity; not run |
| 4 | Odd-lot handling | **Partly tested**: in `probe_4`, in 122 of 658 disagreements every order ahead of the executed one was an odd lot (about 19%), so odd-lot de-prioritisation explains at most that share; 189 executed and 296 skipped orders were odd lots by original size. A variant by remaining size and per-symbol round-lot size (from the R message) is implemented but not yet run on real data |
| 5 | Time structure (hour of day, time since opening cross, last 5 minutes, ETP vs stock, price bucket, burst gap, 10 s after a halt resumes) | **Implemented, not run**: `continuous_dimensions` in the validate JSON |
| 6 | Same-timestamp messages out of matching order | **Partly ruled out**: gap between the two orders' adds is mostly over 1 ms (0 of 658 within 1 us). Experiment `--group-executions 1` (apply executions sharing a timestamp in queue order) is implemented, not run |
| - | Replace keeps priority when price unchanged and size does not increase | **Ruled out as the cause**: 9,337 vs 9,333 disagreements (probe_1 vs probe_0) |
| - | Partial cancel loses priority | **Ruled out**: more disagreements, not fewer (687 vs 658 on the 3-symbol probe; `probe_5` vs `probe_4`) |
| - | Attributed (F) orders, orders created by replace | **Not explanatory** in `probe_4` (0 attributed; 5 executed and 34 skipped orders were replace-created of 658) |
| - | Skipped order's fate | Of 658: 200 later cancelled or modified, 51 executed within 1 us, 7 within 1 ms, 73 later, 1 still resting at the end of the probe |

Current reading: no violation of price priority and no order-state violation; about 2% of executions deviate
from strict FIFO among same-price orders, and the feed does not contain the information (non-displayed
quantity, order-type rules, participant identity) needed to attribute most of them. Real exchanges apply
rules beyond strict price-time FIFO (display priority, reserve replenishment, self-trade prevention, special
order types); this is the most likely home of the residual but it is NOT demonstrated here.
